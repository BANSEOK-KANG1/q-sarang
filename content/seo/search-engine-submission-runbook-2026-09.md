# Q-LOVE 연구 사이트 검색엔진 등록 실행표

대상 사이트: `https://olove-research.kangbs2486.chatgpt.site/`  
사이트맵: `https://olove-research.kangbs2486.chatgpt.site/sitemap.xml`  
최근 문서 피드: `https://olove-research.kangbs2486.chatgpt.site/feed.xml`  
적용 조건: 검색 개선 버전 공개 배포 후 두 주소가 로그인 없이 정상 열릴 때만 진행

> 브랜드 공식 표기는 `Q-LOVE(큐사랑)`이다. 현재 `olove-research`는 2026-09-09에 먼저 등록된 공개 URL 슬러그이며 브랜드명이 아니다. URL을 `qlove-research`로 바꾸는 경우 네이버·Google 속성, 사이트맵, 정규 URL과 기존 외부 링크를 함께 이전한다.

## 1. 공개 직후 기술 확인

1. 홈 응답이 200인지 확인한다.
2. `/robots.txt`에 공개 페이지 허용, 관리 화면 제외, 사이트맵 주소가 표시되는지 확인한다.
3. `/sitemap.xml`에 홈·연구 원칙·근거 허브 1개·근거 유형 랜딩 3개·논문 14편, 총 20개 URL이 있는지 확인한다.
4. 대표 논문 2편의 제목·설명·정규 URL·대표 이미지가 실제 HTML에 있는지 확인한다.
5. 홈과 논문 하단의 `큐사랑 제왕충초 문의 안내`가 정확한 네이버 허브를 여는지 확인한다.

하나라도 실패하면 검색엔진 등록보다 공개 버전을 먼저 고친다.

## 2. 네이버 서치어드바이저

공식 안내: https://searchadvisor.naver.com/doc/wmt_guide_ps_websearch.pdf

1. 네이버 서치어드바이저에서 사이트를 추가한다.
2. 사이트 주소는 프로토콜과 마지막 슬래시까지 정확히 `https://olove-research.kangbs2486.chatgpt.site/`로 입력한다.
3. 소유확인 화면에서 제공되는 HTML 태그 값을 복사한다.
4. 해당 값을 사이트 메타데이터에 추가해 다시 배포한 뒤 소유확인을 완료한다.
5. `요청 → 사이트맵 제출`에서 `sitemap.xml`을 제출한다.
6. 제출 직후 홈과 대표 논문 2편만 URL 검사 대상으로 확인한다.

서치어드바이저는 소유확인된 사이트에서 사이트맵을 제출하도록 안내한다. 인증값은 계정별 값이므로 추정하거나 다른 사이트의 값을 복사하지 않는다.

## 3. Google Search Console

공식 소유확인: https://support.google.com/webmasters/answer/9008080?hl=ko  
공식 사이트맵 안내: https://support.google.com/webmasters/answer/7451001?hl=ko

1. `URL 접두어` 속성으로 정확한 사이트 주소를 추가한다.
2. Search Console이 제공한 HTML 태그 값을 사이트 메타데이터에 추가한다.
3. 다시 배포한 뒤 소유권 확인을 완료한다.
4. `Sitemaps` 화면에서 `sitemap.xml`을 제출한다.
5. 홈과 대표 논문 2편만 URL 검사 후 색인 요청한다.
6. 사이트맵 상태가 `성공`인지, 읽은 URL 수가 16개인지 확인한다.

Google은 사이트맵 제출이 색인을 보장하지는 않지만 발견·오류 모니터링에 사용할 수 있다고 안내한다. 색인이 늦다고 20개 URL을 매일 반복 요청하지 않는다.

## 4. 인증값 전달 형식

사용자가 각 도구에서 받은 값만 아래 형식으로 전달한다.

```text
네이버 소유확인 태그 content 값: [값]
Google 소유확인 태그 content 값: [값]
```

전체 `<meta>` 태그를 받아도 `content` 값만 분리해 적용한다. 인증값은 공개 메타 태그가 되는 값이므로 비밀번호·로그인 쿠키·API 키를 함께 보내지 않는다.

## 5. 등록 후 측정

| 시점 | 확인 항목 | 조치 |
|---|---|---|
| D+0 | 사이트맵 수집 성공·오류 | 오류가 있으면 URL·robots·정규 URL 수정 |
| D+3 | 홈·대표 논문 색인 여부 | 미색인이어도 중복 페이지를 만들지 않음 |
| D+7 | 노출수·검색어·클릭 | 제왕충초·코디세핀·브랜드 검색어 분리 |
| D+14 | 논문별 노출과 문의 허브 클릭 | 노출은 있으나 클릭이 없으면 제목·설명만 한 차례 개선 |
| D+30 | 검색 방문→네이버 허브→문의 | 경로별 수치와 문의 코드 대조 |

측정값은 `content/seo/search-engine-submission-tracker.csv`에 기록한다.

## 6. 다음 확장 조건

- 실제 검색 노출이 생긴 질문만 후속 요약이나 FAQ로 확장한다.
- 사람·동물·세포·리뷰 근거를 섞지 않는다.
- 제품 효능이나 질병 예방·치료 효과로 연결하지 않는다.
- 독립 도메인을 사용할 경우 기존 URL에서 새 도메인으로 정규화·리디렉션 계획을 먼저 세운다.

## 7. 2026-09-09 실행 상태

- Google Search Console에 URL 접두어 속성을 추가하고 HTML 메타 태그 방식으로 소유권 확인을 완료했다.
- 확인 태그를 포함한 연구 사이트 버전 5를 기존 공개 주소에 배포했고, 공개 HTML에서 태그가 유지되는 것을 확인했다.
- `sitemap.xml` 제출 뒤 상태 `성공`, 마지막 읽은 날짜 2026-09-09, 발견된 페이지 16개를 확인했다.
- 홈 URL 검사는 Search Console의 일시 오류 안내가 발생해 색인 요청을 반복하지 않고 후속 점검 대상으로 남겼다.
- 네이버는 이용약관 동의 뒤 사이트를 추가하고 HTML 메타 태그를 공개 배포했다. 첫 HTML 파일 확인은 호스팅의 `.html` 주소 정규화로 404가 발생했으나, 전용 확인 경로로 교체한 버전 8을 배포한 뒤 소유확인을 완료했다.
- 2026-09-09 20:57 KST에 사이트맵을 등록했고, 20:57~20:58 KST에 홈·대표 리뷰·사람 대상 연구 글 총 3개 URL만 수집 요청했다.
- 신규 사이트이므로 네이버 요약 화면의 콘텐츠 노출·진단·수집 리포트는 아직 데이터 생성 대기 상태다.

## 8. Q-LOVE 브랜드 정정

- 2026-09-09 21:32 KST에 사이트 화면, 헤더·푸터 로고, 검색 제목·설명, Open Graph 이미지, 저자·발행자 표기를 `Q-LOVE(큐사랑)`로 통일했다.
- 512×512 Q 심볼 검색 아이콘과 Apple 아이콘을 추가했다.
- 홈에 `Organization`, `WebSite`, `CollectionPage` 구조화 데이터를 연결하고 `Q-LOVE`, `큐사랑` 대체 이름과 네이버 블로그를 동일 브랜드 채널로 표시했다.
- 공개 홈 HTTP 200, Q-LOVE 제목, 로고·공유 이미지, 검색 아이콘, 네이버 확인 파일 HTTP 200을 재검증했다.

## 9. 검색 발견·공유 개선본 배포 후

1. 공개 홈·대표 논문·`/feed.xml`이 모두 HTTP 200인지 확인한다.
2. 대표 논문 HTML에 Article과 BreadcrumbList 구조화 데이터가 함께 있고, 화면에 공유·주소 복사 버튼이 보이는지 확인한다.
3. `robots.txt`가 `/sitemap.xml`과 `/feed.xml`을 모두 안내하는지 확인한다.
4. Google Search Console에는 기존 `sitemap.xml`을 유지하고 `feed.xml`을 추가 사이트맵으로 한 번만 제출한다.
5. 네이버에는 기존 XML 사이트맵 등록을 유지하고, 변경된 홈 URL만 한 번 재수집 요청한다. 같은 URL을 반복 제출하지 않는다.
6. 배포 72시간 뒤 Q-LOVE·큐사랑·제왕충초 관련 노출과 클릭을 확인한다.

RSS는 최근 URL 발견을 보조하는 경로이며 색인이나 순위를 보장하지 않는다. 기존 16개 정규 URL은 주소를 바꾸지 않는다.
